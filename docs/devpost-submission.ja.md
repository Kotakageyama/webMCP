# TaskSurface — Devpost 提出文案（日本語版）

## プロジェクト名

TaskSurface

## タグライン

ライブの WebMCP capability を、人とエージェントが共有するタスク専用ワークスペースへ変える。

## ライブアプリとソース

- ライブアプリ: https://tasksurface-nlgt6zklja-an.a.run.app
- ソース: https://github.com/Kotakageyama/webMCP

## 着想

WebMCP により、エージェントはクリックを推測する代わりに、ページネイティブな構造化ツールを使えます。しかし構造化されたツール呼び出しだけでは、人に「何が変わるか」「エージェントがどこで作業しているか」「どこで人の判断が必要か」は伝わりません。人とエージェントが解決しているタスクを UI が表す Web のあり方を探求しました。

## 何をするアプリか

TaskSurface は EC 運用のプロトタイプです。店舗担当者は通常の注文管理画面から、商品返品、配送先変更、出荷キャンセルのいずれかを選びます。

注文 UI は共有ワークスペースへ変化し、タスクに必要な事実と選択肢だけを残します。エージェントの現在のコンテキスト、ページで利用可能な capability、確定前の業務的な意味を持つプレビューを示します。担当者は返金先や住所を変更し、明示的に承認してから実行します。サーバーも担当者承認のないアクションを拒否します。

## なぜ WebMCP か

TaskSurface は既存ダッシュボードにチャットサイドバーを足したものではありません。情報源はライブのページ capability セットです。WebMCP 対応ブラウザでは `document.modelContext.registerTool` が現在の状態で役立つツールだけを公開します。注文全体の画面ではタスク開始ツール、返金・住所・出荷タスク中は読み取り・準備ツールに切り替わります。状態変更時には以前のツールを解除します。

そのため UI はエージェントが見る capability グラフと同じものに反応します。人はエージェントが今できることを理解し、決定点で介入し、JSON やクリック履歴ではなく意味のある結果を確認できます。

## 実装

アプリは Next.js 16 で構築し、Google Cloud Run にデプロイしています。注文データと承認済みアクション記録は Neon Postgres に保存します。Cloud Run は専用サービスアカウントを通じて Google Secret Manager からのみデータベース URL を読みます。リポジトリには Neon スキーマ、Cloud Build 設定、Dockerfile、デプロイ手順が含まれます。

WebMCP 登録は `app/webmcp.ts`、タスク画面と人の承認フローは `app/task-surface.tsx` に実装しています。API は承認済みの返品・配送先変更・出荷キャンセルのみを保存します。

## 直面した課題

ツールスキーマだけでは、常に適切な人間向け UI を表現できません。MVP では対象領域を意図的に限定し、商品カード、返金先ラジオカード、住所フィールド、重要操作の確認ゲートといったタスク専用コンポーネントを使いました。これにより capability モデルを理解しやすくしつつ、将来の schema-to-component ヒント拡張の余地を残しました。

## 誇りに思う点

- WebMCP をエージェントだけでなく人にも見えるものにした。
- 構造化されたツールの可用性から、適応的で集中した作業画面を作った。
- 所有者を示す UI、意味的プレビュー、UI と API の両方での承認ゲートで、人の判断を維持した。
- 静的 UI コンセプトではなく、実際の Postgres 永続化を備えた公開フルスタックデモを提供した。

## 学び

最も魅力的なエージェントネイティブ UI は、しばしば「より少ない UI」です。エージェントがライブ capability を発見できるなら、人には現在の作業を監督・修正・承認するための情報だけを見せるべきです。

## 今後

開発者提供の UI ヒントによる高度な JSON Schema マッピング、複数商品の返品、意味的な undo を伴う履歴、複数の Web アプリをまたぐマルチエージェントの存在表示を追加する予定です。

## 推奨デモフロー

1. 注文 `TS-1042` を開き、通常の注文ダッシュボードを見せます。
2. 「Return an item」を開始し、返品に集中した画面へ変わる様子を見せます。
3. ライブツール、エージェントの存在、意味的プレビューを示します。
4. 人が返金先を Visa からストアクレジットへ変更します。
5. 承認チェックを入れて返品を確定します。
6. 配送先変更と出荷キャンセルにも同じ画面パターンを使えることを簡潔に見せます。
